## Changes

- Stop appending every character to each play set's `PlayableAvatars`. This list is also exposed to other game systems; permission to enter must not redefine its membership. Existing lists, their order, and earlier mods' entries remain unchanged.
- Restore the four native character-swap branches. The old patch forced the result of a playset comparison and set a player-manager state flag. This is a lifecycle/resource decision, not simply a rejection check.
- Copy membership into a separate ownership map and register avatar names from actor tables. The Toy Box's `PlayableAvatars` contains only a small subset of its actual characters, so it cannot identify every visitor. Specific playset homes take precedence regardless of table loading order; crystal and base records share the same home. When creating a known visitor, preserve its base actor instead of selecting another world's `_PS` variant. Unregistered actors keep the engine fallback.
- Load all playset dependency maps using the engine's existing Toy Box branch. The previous patch loaded all actor lists but only the current dependency map. Dependency records supply character stat packages, animation choreography and tool resources. For example, Toy Box data contains all avatar stat packages and Perry's combo choreographies. Loading actor names alone does not provide these records. Preserve the engine's paired unload flag and verify both loader and unloader signatures.
- Set both `WantToyBoxFX=true` and `WantBloatFX=true` for the six play sets. Motion-event effects have a separate filter from Toy Box tool effects. These are general playset settings; there is no Perry/Incredibles exception and no tool or unlock grant.
- Add rollback for failed native installation and remove the character feature if its script loader cannot install. All code signatures and relevant calls are verified before editing memory.

The option remains off by default and requires `[Mods] Enabled=1`. It adds no timer or frame polling. The character variant detour runs only when the engine adjusts an avatar name. Native character-to-playset lookup, car classification, character group masks, save data, and unlock requirements are not patched. Reward amounts remain original unless the explicit temporary test multiplier is enabled. Statistics are made available through normal dependency loading instead of synthesizing experience awards.

## Gameplay acceptance checklist

Use an existing unlocked vehicle and the original vault requirements. Keep a backup of the test save. Do not reset character progress to test this change.

1. In Incredibles, compare a home character, Jack Sparrow or Sulley, and Perry. Repeatedly enter/exit a vehicle, summon it again, jump, attack, equip/unequip a tool, and move immediately afterward. Check collision on the same route at a normal frame cap as well as the usual cap.
2. Gain experience with a home character and a visitor, then with a Toy Box character. Record levels/progress before and after a known experience reward and after reload. Distinguish the level cap from a failure to gain experience.
3. Summon an already unlocked playset vehicle with both a home character and a visitor. Check the action/menu route, not only the vehicle actor loading.
4. Test a vault requiring that play set's collection of characters. It should retain the original required roster; it should not demand every DI1 character or bypass collection progress. Confirm the reported object's identity before diagnosing it as an Avatar Vault.
5. Compare Perry's visible combo swing, hat projectile and particles in Incredibles and the Toy Box. Also compare at least two other visiting characters in another playset, such as Rapunzel and Jack Sparrow; this is a general dependency repair.
6. Check playset transitions, death/respawn, crystal variants, two players, and pedestrians in Cars. Cars races and character-specific mission abilities retain native restrictions.
7. Restart with the option off and confirm the original behavior. Check for `character_playsets` and `character_actor_registry` messages when the option is on; the latter appears when actor tables load.
