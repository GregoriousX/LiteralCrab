# Play set features

## Character tools across playsets / Narzędzia postaci w playsetach

Gameplay feedback confirms the Pirates flintlock works. Full Pirates mission coverage remains unverified.

The optional `literalcrab_mu_scare` companion is an **experimental** hand-held megaphone for MU. It requires `CharactersInAnyPlayset=1` and `[Mods] Enabled=1`; without active character freedom its assets are withheld. The companion adds its item to all 26 supported biped inventory profiles, preserving their existing group order and default selections; 51 other profiles remain unchanged. Its separate Items entry uses an original scare weapon through the native tool firing/owner pipeline. Normal combo attacks, the hidden native megaphone ability, back packs and profile unlocks are preserved. `ToolsInAnyPlayset` can widen its native MU world restriction. Build the companion from your own original assets with `python di1/tools/build_mu_scare.py <game-assets> <new-output-folder>`, then copy its `mods/literalcrab_mu_scare` folder beside the matching ASI. Disable it with `[Mod] Enabled=0` in that folder's `user.ini`. The earlier blaster prototype appeared in game but failed to scare. The current experimental script instead adds a separate scare weapon to the avatar, releases/removes its slot after the original firing window, and sends the original ScareAttack message to the avatar. It preserves the 644 original weapon definitions, uses a Mike icon, and removes gun muzzle choreography and gun sounds. Scaring a target with a visiting character is gameplay-confirmed; mission completion is not independently confirmed. With the matching updated playset animation provider, a separate private tool message plays Mike's original megaphone scare gesture through an added alias on the native override channel. It stops after completion or a tool change without replacing normal attacks or gun clips. The gesture and return to movement are gameplay-confirmed with a visiting character. Sound and green scare FX are also gameplay-confirmed with the same visiting character. The companion explicitly preloads the original Mike audio bank and scare choreography. The tool script explicitly plays the original standard scare yell and green choreography, attaching the effect to the avatar's Cntrl_Main control through the original native choreography API. The private gesture alias omits those AV metadata events to prevent duplicate playback. Preloading resources alone was gameplay-tested and did not restore AV. Full-roster body/contact fit is not independently confirmed. Building this hand-tool companion alone does not generate the provider's gesture aliases; the matching updated animation provider is also required. Only its exact `_name` dictionary key is redirected to the original `ITEM_MIKE_name` skill label, preserving native localization and all other text/selection IDs. The label uses the existing native localized skill name. Other mods replacing `var/toolset/toolset.bin` conflict with this companion.

It preserves personal equipment and dependent abilities; buying a shared toy does not make it available in every playset. For example, the Toy Box Blaster stays restricted in Lone Ranger, while Buzz's innate Pixar Ball can work in Incredibles. Shared equipment remains available wherever the original game allows it, including Toy Box and its own playset. Suppression and progression checks still apply. The regression tests cover both blaster variants, shared equipment without an upgrade prerequisite, per-avatar Pixar Ball eligibility, and the early inventory refresh path. Gameplay confirmation of this restriction fix is pending.

Earned equipment can retain progression across playsets within the same player profile. The original lock-state code copies a completed native unlock (state 6) from the home-playset state into the profile states. The native `ProfileLocks` export/import path preserves that earned state, while `PlaysetLocks` separately restores local state. A private-image replay of the original PC setters, getters and saved-field export/import passed 460 checks for `UP_HoverBoard` and `UP_JetPack`, including foreign worlds, unearned states and UID isolation. Only encryption transport was simulated; live save files and full gameplay were not exercised. This supports unlock-once/use-elsewhere with `ToolsInAnyPlayset`; no mission-progress merge or additional grant is needed for this mechanism.

## Toy Store Infinity

With `[ToyStore] Infinity=1`, every play set gets a second Toy Store, **Toy Store Infinity**, in the pause menu (between the online and settings entries) and in the Infinity kiosk (below the Toy Store). It uses the Toy Store's own screen, icons and descriptions, so you can drive the Toy Box or another play set's car in Cars with your own character, or ride a horse in Pirates.

- **What is listed:** vehicles and mounts, that is toys of the vehicle category or toys the game can summon, from every world: the Toy Box (Autopia Car, the Wreck-It Ralph karts, Tron, the stunt buggy and copters, the Incredibles car and copter, the Lone Ranger horses, Archie, Bullseye and so on) and the play sets (for example the Monsters University bikes). A play set loads only its own and the shared toy data, so LiteralCrab reads the other worlds' vehicles, their placeable-object rows, their behavior and animation dependencies (about 120 small files; the models still load only when placed) and their names from the game files at startup and adds them to the play set in memory; a model offered twice is listed once. Things that only work on a play set lot or socket (buildings, decorations, a ship's wheel, trains and tracks) and ordinary Toy Box toys are left out.
- **Unlocked toys:** the Toy Box's are all unlocked in Gold; a play set's are listed once the game counts their recipe card as bought, exactly as tools unlocked in one world are usable in another: the card's state where the current world loads it, otherwise the card's lock, which the game answers from the player's profile for other worlds. `InfinityAll=1` also lists the locked ones.
- **Names and descriptions** come from the game's own world dictionaries, in the language the game is using (recognised from the pause menu texts): whatever dictionary files are in effect, shipped or replaced by a language pack or loose files. A toy without a description in that language shows the English one, or none.
- **Riding and driving:** a character's play set version only has the ride and drive animations of its own world (Mr. Incredible has no horse riding in the Incredibles). With Toy Store Infinity on, each character's play set version also gets the mount, bike, car, kart, rowboat and ship animations it lacks from that same character's Toy Box version, in memory and only when both use the same animation layout; animation mods for these characters are kept.
- **Bikes everywhere:** the Monsters University bikes are mounted with the native interaction outside Monsters University too; their ride script and destruction models load with the other worlds' vehicles.
- **Pirates' sea:** the sea has a water surface vehicles could drive on, while characters die in water triggers below it. A driven vehicle low on the water above such a trigger (or inside it) is now killed the way other worlds' water does, and its native respawn sets it back on land; rowboats and ships are untouched. Very close to the shore a bike can occasionally sink too.
- **Free and temporary:** choosing *Place* puts the toy beside you, like the Toy Store does after a purchase. Nothing is bought, no sparks or coins are taken, recipe cards, "new" marks and inventory counts are untouched, and nothing is unlocked. Placed toys are not saved: the store places copies marked with the game's own "do not save" flag (`M_NoSave`, as on the Toy Box Buzz ride), so a play set save never depends on Toy Store Infinity.
- **The ordinary Toy Store is unchanged,** and the entry is not offered outside play sets, during missions, activities or adventures.
- **Pirates** has no placeable-object data of its own; Toy Store Infinity gives it an empty package in memory, filled like the others. `LiteralCrab.log` lists the store's toys and names what was placed.

Po polsku: `[ToyStore] Infinity=1` dodaje w każdym playsecie drugi sklep, **Toy Store Infinity**, w menu pauzy i w kiosku Infinity (pod zwykłym Toy Store).
